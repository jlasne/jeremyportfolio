Build your app’s style guide

The 6 rules brand designers use, adapted to apps. Then match colors and fonts from 12 top apps, and copy the prompt that makes your AI apply them.

Method adapted from the brand style guide of Emilie Rouchy, art director, shared on Instagram.

6 principles

  1. 1

    A number in every rule

    “2 fonts at most” can be checked. “Keep it clean” cannot.

    Duolingo’s cards keep 2 pt borders and a 4 to 6 pt bottom edge.
  2. 2

    A role for every element

    Each color and each font has 1 job, written next to it.

    Strava’s orange #FD5200 marks only the active tab, selected chips, routes and the Save button.
  3. 3

    A closed set

    Few elements, always the same ones. People recognize what repeats.

    Rise sets every word in 1 family, Work Sans, at 3 weights.
  4. 4

    A don’t for every rule

    Next to each rule, write what never happens. It stops the drift between screens.

    Rule: orange marks the main button only. Don’t: an orange headline.

  5. 5

    A version for every context

    Plan light and dark screens, and the icon in color and in 1 color.

    Headspace turns its sleep screens navy #101340.
  6. 6

    One screen that shows it all

    A sample screen applies every rule at once. It tests the guide.

    Ladder’s lime #E6FF01 fills the main button, done days and rings, next to white text on #0E0E0E.

5 steps, in this order

  1. 1

    Colors

    Pick 1 main color, a dark base, a light base and 1 or 2 accents. Write each HEX and RGB, its share (60, 30, 10) and the pairs that work. Text needs a 4.5:1 contrast.

  2. 2

    Type

    2 fonts at most: a bold one for titles, a readable one for text, and the system font as backup. Set 4 levels, title, subtitle, body and caption, each with a size and a weight.

  3. 3

    Icon

    Make 4 versions: full color, 1 color, on light and on dark. Check it at home screen size and at search result size.

  4. 4

    Components

    Buttons, cards, inputs and tabs: 1 corner scale, 1 spacing scale and 3 states each, default, pressed and disabled.

  5. 5

    Composition

    Build 1 sample screen with 5 rules: 1 hero, 3 colors, 1 main button, equal margins, the title and the tabs always in the same place.

Under every step, add 3 don’ts, like a 4th color, a 3rd font or 2 main buttons on 1 screen. Colors, type, icon and composition make an app consistent; the rest adds personality.

The test. Give the guide to Claude Code and ask for a new screen. If the screen is right on the first try, the guide works.

3 big prompts

Write my app’s style guide

Use it when your app has no written design rules, or its screens drifted apart.

Read my app’s code and screens, then write DESIGN.md, my style guide. Change no code yet. Follow 6 principles: 1. A number in every rule: “2 fonts”, “3 colors per screen”, “1 main button”. 2. A role for every element: each color and font has 1 job, written next to it. 3. A closed set: keep the fewest colors, fonts, sizes and corners that cover every screen. 4. A don’t for every rule: write what never happens. 5. A version for every context: light and dark, the icon in color and in 1 color. 6. One sample screen that shows every rule at once. Write 5 sections, in this order: 1. Colors: list every color in the code and where it appears. Keep 1 main, 2 bases (dark and light) and 1 or 2 accents. Give HEX, RGB, the share (60, 30, 10) and the pairs that pass 4.5:1 for text. 2. Type: 2 fonts at most, plus the system font as backup. Define title, subtitle, body and caption with size, weight and line height. 3. Icon: 4 versions: full color, 1 color, on light, on dark. 4. Components: buttons, cards, inputs and tabs with sizes, corners, spacing and 3 states. 5. Composition: 1 sample screen with 5 rules: 1 hero, 3 colors, 1 main button, equal margins, fixed spots for the title and the tabs. Under each section, write 3 don’ts. End with a table: each value in the code today, and the token that replaces it. Check: - Every rule holds a number. - 3 colors and 2 fonts at most, plus neutrals. - Someone who never saw the app can build a new screen from DESIGN.md alone.

280 words

Apply my style guide to every screen

Use it when DESIGN.md exists, and the screens do not follow it yet.

Apply DESIGN.md to every screen of my app. Keep features, data and copy. 1. Turn every color, font, size, corner and spacing of DESIGN.md into a named token, in 1 file. 2. Replace every hard-coded value in the code with its token. For a value with no token, use the closest one and list it. 3. Go screen by screen, in this order: onboarding, home, the main action, settings, the paywall. 4. On each screen, apply the 5 composition rules: 1 hero, 3 colors at most, 1 main button, equal margins, the title and the tabs in their fixed spots. 5. Add the dark version of every token that DESIGN.md defines. 6. Fix every don’t you find, and name the rule it broke. Report per screen: rule, before, after. Check: - Zero hard-coded colors and font sizes in views. - 1 main button per screen. - Text passes 4.5:1 on its background, in light and dark.

156 words

Check my screens against my style guide

Use it when before a release, to catch what drifted.

Audit my app against DESIGN.md. Change no code. For each screen: - Colors: list every color used. Flag values outside the tokens, and an accent that covers more than 10% of the screen. - Type: flag a 3rd font, a size outside the scale and a heading that breaks the hierarchy. - Components: flag a corner, padding or height outside the scales, and a missing state (pressed, disabled, empty, error). - Composition: count the heroes and the main buttons, and flag more than 1 of each. Flag uneven margins, and a title or tab bar out of place. - Contrast: flag text under 4.5:1 and large text under 3:1, in light and dark. - Don’ts: flag every don’t of DESIGN.md that the screen shows. Then: 1. Rank the screens by number of issues. 2. Give the 5 fixes that remove the most issues. 3. Propose rules for DESIGN.md where the screens agree but the guide says nothing. Report as a table: screen, rule, what breaks it, the fix.
