# Grid Tycoon: engineering design

`SPEC.md` is the product spec. This file is the contract between the parts of the codebase: where things live, what each module exports, and how every gap in the spec is filled. When the spec and this file disagree, the spec wins on rules and this file wins on mechanics it explicitly decides.

## 1. Where it lives

- Public URL: `https://www.jeremylasne.com/games/`. The game opens straight on its title screen there; there is no hub page.
- The site is a static Vercel project with no build step. The app builds with Vite into `app/dist/`, and `app/scripts/publish.mjs` copies it to `games/` (index.html + assets/ + sprites/ + cover.png ...), which is committed. The source stays in `games/grid-tycoon/`; `vercel.json` redirects `/games/grid-tycoon/*` to `/games/` so the source folder is never a page.
- Vite `base` is `/games/`. Load runtime files with `import.meta.env.BASE_URL + 'sprites/atlas.json'`, never a hard-coded path. No client router: one page, state-driven screens. A multiplayer invite is `/games/?room=ABCDEF`.
- **Multiplayer ships offline for now.** There is no Supabase project yet: `src/net/config.ts` holds empty URL/key, `isOnline()` returns false, and the title screen shows multiplayer as offline (host/join disabled with a one-line reason). All the multiplayer code (schema, edge function, client, lobby, timer UI) is built and tested against an in-memory room server so it can go live by filling the two config values and deploying `supabase/`.

## 2. Engine (src/engine)

Pure TypeScript. `src/engine/types.ts` is the data model, `src/engine/index.ts` the public API; both are fixed contracts. Implementation may be split into any modules, but nothing outside `src/engine` imports anything but `src/engine/index.ts`. No `Math.random`, no `Date`, no DOM. Every number comes from `config/balance.json` through the `config` argument.

### 2.1 Rounds and timing

- `state.round` is the round being decided (1..40). `resolveRound` resolves it and returns `round + 1`. After round 40, `round = 41` and `finished = true`.
- **Build timers count down at the end of each resolution.** An order placed in round t with build time N (small 1, big 3, upgrade 4, link 1) is online from round t + N. So "1 round" and "next round" both mean usable next round, and a decision phase only ever allocates what is already online. The spec's step 1 ("advance timers, finished buildings come online") is run as the last step of the previous resolution; the timing is the same and the decision phase never has to guess. `RoundResult.completed` lists what finished.
- An upgrading building keeps delivering 2 MW until it finishes, then becomes size big, 10 MW, online.
- Starting buildings: small plant at lot [0,0], small datacenter at lot [1,0], internal link 2 MW, all online, `builtRound` 0, pricePaid 10 and 12.

### 2.2 Decision-phase effects (applied first inside resolveRound, in this order)

The UI shows these instantly in the draft (`previewCompany`), but they only become real at resolution.

1. **Forced sales** (only if `treasury < 0` at the start of the phase). Each sold building returns `sellBackRate × pricePaid` (rounded to 2 decimals) and is removed. If every building is sold and treasury is still below 0, the engine issues `ceil(-treasury / sharePrice)` shares at the current price (no 20% cap). Validation requires the sales to bring treasury to 0 or above, or to sell every building. Finance and builds come after and cannot replace forced sales.
2. **Early repayments** `loans.repay[loanId] = amount` (partial allowed, ≤ principal, ≤ treasury). A loan at 0 principal is removed.
3. **Refinance** `loans.refinance` lists loans with `dueRound === state.round`. Refused (validation error) if `treasury < 0` at the start of the phase. A refinanced loan pays this round's interest as usual; at step 7 its principal is not paid but rolled into a new loan at the current `loanRate`, `dueRound = round + termRounds`.
4. **New loan** `loans.take > 0`: one new loan, `annualRate = loanRate(state)` fixed now, `dueRound = round + termRounds - 1`, `takenRound = round`. Cash lands at once. Interest is charged in rounds `takenRound..dueRound` (8 times) and the principal at `dueRound`. Example: 20 at 8% pays 0.40 per round for 8 rounds and 20 in the 8th.
5. **Shares** `mode: 'issue' | 'buyback'`, integer `count` ≤ `floor(maxChangePerRound × shares)`, at the current `sharePrice`. Issue: cash in, shares up, market cap and business value unchanged. Buyback: cash out, shares down; cash ≤ treasury − total debt (after this round's loan and repayments). Never both.
6. **Upgrades** then **builds**: cost leaves treasury. Treasury must stay ≥ 0 after all of it. Build tile: a free lot `[col,row]`, `0 ≤ col < plot.lotsPerRow`, `row ≥ 0`; if omitted, `findFreeTile`. Link orders: `{ kind: 'link', use, mw }`, integer mw ≥ 1, cost `costPerMw × mw`, a new Link with `roundsLeft 1`. Several link entries of the same use add up.

### 2.3 Resolution (engine, fixed order)

0. Sanitize every decision; missing human decisions use `defaultDecision`, bots use `botDecision` (bot decisions are computed from the pre-resolution state, then resolved together with everyone).
1. Apply decision-phase effects (2.2) for every company.
2. **Demand.** For each pool in the order citizens, otherDc, cloud, btc, ai, draw one `eps ~ N(0,1)` from the state RNG:
   `E_t = 0.7 E_{t-1} + 0.3 g_{t-1}`, then `g_t = clamp(g_{t-1} + 0.3 (mu − g_{t-1}) + sigma eps, −10%, +20%)`, `D_t = D_{t-1} (1 + g_t)`. Start values: `g_0 = E_0 = mu`, `D_0 = startPerCompany × number of companies`. Demand is not rounded (MW), money is.
3. **Rent.** otherDc demand this round = background `D_t` + sum of every company's `rentMw`.
4. **Allocation** with `allocatePool` for every pool, among non-bankrupt companies. Offers: citizens = `power.town`, otherDc = `power.otherDc`, cloud/btc/ai = `compute.*`. U = `pool.lastUsed[id]` (0 if absent). After allocation `lastUsed = used`.
   Rent matching (`matchRent`): rivals' otherDc sales fill rent first, split in proportion to each request, and a renter's own otherDc sales never fill its own rent (SPEC: "other companies"); `fromMarket = rentMw − fromRivals`. All rented MW is delivered (the market fills the rest), so datacenter powered MW = `power.internal + rentMw`.
5. **Revenue and costs.**
   - revenue = Σ used × rate.
   - own power used = town used + otherDc used + internal consumed, where internal consumed = `clamp(computeUsed − rentMw, 0, power.internal)` (rented MW is paid anyway, so it is consumed first). Power cost = 0.4 × own power used.
   - rent = 1.3 × fromRivals + 1.6 × fromMarket (a contract: paid on every MW requested).
   - maintenance = 2% × pricePaid of every building not in status `building` (online and upgrading pay; upgrade cost is added to pricePaid when ordered).
   - interest = Σ principal × annualRate / 4 over every loan held this round.
6. profit = revenue − power − rent − maintenance − interest; treasury += profit.
7. **Due loans** (`dueRound === round`): refinanced → rolled (2.2.3); otherwise the principal leaves treasury ("fail" = treasury goes below 0, handled by the losing round rule next phase).
8. Treasury below 0 → the next decision phase is a losing round (forced sale screen). Nothing else happens now.
9. **Stock.**
   - `dRev = (rev − prevRev) / prevRev`; round 1 (no previous round) → 0; prevRev 0 and rev > 0 → +30%; both 0 → 0. Clamp ±30%.
   - weights `w_p` = share of revenue from each pool in the previous round (all 0 on round 1 or with no revenue).
   - idle = `1 − (plantUsed + dcUsed) / (plantMw + dcMw)` with plantUsed = own power used, dcUsed = compute used; 0 if no capacity. `P_idle = max(0, idle − idleFree) × idlePenaltyPer10 × 10` (continuous: 1% per 10 points).
   - `r = 0.5 × clamp(dRev) + Σ w_p (g_p − E_p) − P_idle`.
   - `FV = profitMultiple × max(mean profit of the last profitWindow rounds incl. this one (fewer if not played yet), 0) + bookWeight × Σ pricePaid of all buildings (under construction included, links excluded)`.
   - `BV = 0.85 × BV_prev × (1 + r) + 0.15 × FV`.
   - `debt` = principal outstanding at the start of this resolution's step 7 (after the phase's new loan and repayments, before due principal is paid). `c = min(1, (interest + principal due and not refinanced) / revenue)`; revenue 0 → c = 1 if the numerator is above 0, else 0. `MC = max(BV − debt × f(c), floor)`, `f(c) = (e^{kc} − 1)/(e^k − 1)`, k = 3.
   - `sharePrice = MC / shares`. MC at the floor → `bankrupt = true` from now on: it no longer decides or sells, its `lastUsed` entries are deleted so its MW frees up next round, it ranks last.
   - Stock breakdown in price units (shares = this round's shares): revenueGrowth = 0.85 BV_prev × revTerm / shares; demandMiss_p = 0.85 BV_prev × w_p (g_p − E_p) / shares; idle = −0.85 BV_prev × P_idle / shares; fundamentals = 0.15 (FV − BV_prev) / shares; debtDrag = (drag_prev − drag_now) / shares where drag = debt × f(c) of that round (0 before round 1); shares = MC_prev / shares_now − MC_prev / shares_prev (the issue/buyback effect). They sum to priceAfter − priceBefore within rounding, where priceBefore = last round's price.
10. **Timers** (see 2.1): every building and link with roundsLeft > 0 counts down by 1; reaching 0 → online / big / carrying. Then results: `RoundResult` per company, `RoundSummary` (pool demand incl. rent, growth, expected, total used, ranking by used, prices, price ranking) appended to `state.history`, ranks set, `lastDecision` stored.

Money (treasury, revenue, costs, profit, prices, BV, MC) is rounded to 2 decimals at the end of each step with `round2`. MW stay unrounded.

### 2.4 Validation (strict) and sanitizing (lenient)

`validateDecision` returns every issue with a code (see `ValidationCode` in types.ts). It checks, in phase order: bankrupt / finished; forced sales (allowed only when treasury < 0, must reach ≥ 0 or sell all); repayments; refinance (due this round, treasury ≥ 0); shares (not both, integer, ≤ 20%, buyback ≤ treasury − debt); upgrades (own small online building, not twice); builds (valid kind/size/use, integer mw ≥ 1 for links, free in-plot tile, no two orders on one tile); treasury ≥ 0 after everything; allocations: every number finite and ≥ 0; `power.town ≤ town link` (`no_town_link` when the company has no carrying town link and town > 0); `power.internal ≤ internal link`; `internal + town + otherDc ≤ plantMw`; `rentMw ≤ import link`; `cloud + btc + ai ≤ min(dcMw, internal + rentMw)`. Capacities are this round's (`capacity(company)` after forced sales; builds placed now do not count).

`sanitizeDecision` clamps allocations to the caps (compute is scaled down proportionally, then floored to keep validity), drops invalid builds/upgrades/finance items, and in a losing round picks forced sales itself (cheapest sell value first until treasury ≥ 0). `resolveRound` always sanitizes, so it never throws on input.

### 2.5 Helpers for the UI

- `defaultDecision`: last round's power/compute/rent, sanitized to current capacity. Round 1 (no lastDecision): internal = min(plantMw, internal link), compute ai = min(dcMw, internal), rest 0. The draft of every decision phase starts from this.
- `previewCompany(state, id, draft)`: treasury left after the draft's forced sales, finance and builds, current capacities (the draft's builds are listed as pending), debt, price/shares after the share action.
- `projectRound(state, id, draft)`: estimated profit with last round's demand. Per pool: `estUsed = min(offer, U_self + max(0, D_last − ΣU_last))`, where D_last is the last summary's demand (start demand before round 1) and ΣU_last the pool's total last used. Costs as in resolution (rent at 1.6 for the share rivals did not fill last round, else 1.3), maintenance, interest. `marginPerMw` per pool = rate − own power cost (0.4) for the allocate panel.
- `warnings(state, id, draft)`: `idle_high` (projected idle > idleFree), `link_short` (power.internal or power.town above link capacity), `no_town_link`, `rent_over_import`, `compute_unpowered` (compute above powered MW), `loan_due_soon` (a loan with dueRound ≤ round + 2), `treasury_negative` (after the draft). Labels are short ("Idle 34%"), detail is one sentence.
- `loanRate`: `baseRate − stabilitySpread × Σ w_p stability_p (+ stressAdd if treasury < 0 or last profit < 0)`, weights from the last round's revenue (0 before round 1, so 12%).
- `riskView`: estimated revenue = last revenue × (1 + Σ w_p g_p of last round); interest next round on all loans incl. the draft's new one; debt cost share = (interest + principal due next round)/est revenue (capped at 1); market cap drag = total debt × f(that share); next due loan.
- `revenueByBuilding`: last round's power revenue split over plants by MW, compute revenue over datacenters by MW (for coins over buildings).

### 2.6 Bots (deterministic, no RNG, public information only)

Shared rules: build when treasury > 1.5 × the next build's cost; shift MW toward the pool where their used share (used / offered) was highest last round; keep idle under 25%; always keep links sized to what they route (buy link MW the round before it is needed, i.e. along with the build); handle losing rounds with sanitize's forced sales. Styles:

- **Volta Utility**: builds plants first, big when affordable; buys a town link early; sells to citizens, cloud, then rivals (otherDc); borrows little (at most one loan, small), never buys back.
- **Nimbus Compute**: builds datacenters (and import links), rents power for the gap; compute AI first then cloud; borrows up to 50% of its market cap.
- **Hashfield Mining**: small plants and small datacenters only; compute on bitcoin, extra power to rivals; issues shares (up to the cap) when treasury is low and it wants to build.

Bots must stay valid (run their output through sanitize) and should not go bankrupt in normal seeds. `npm run balance` runs 20 bot-only games and reports finishing prices; bots should finish in a spread, not identical.

### 2.7 Determinism

All randomness: the state's mulberry32 (`rngState`), drawn only in step 2, one normal per pool per round (Box-Muller, 2 uniforms). Same seed + same decisions → deep-equal states. Ids from `nextId`. Iterate companies in array order, pools in POOLS order.

### 2.8 Tests (Vitest, `src/engine/*.test.ts`)

Every acceptance test in SPEC.md is a named test, plus: allocation edge cases (zero demand, no offers, all incumbents), timers (small online next round, big after 3, upgrade keeps 2 MW for 4 rounds then 10), rent matching (rivals first), validation of each code, sanitize always validates (property test over random decisions with a local seeded generator), 40-round determinism, no NaN anywhere after 40 rounds of bots for 50 seeds, money always 2 decimals.

## 3. App state (src/store)

Zustand stores. Components read with selectors; no engine call in render loops except through the memoized derived hook.

```ts
// src/store/game.ts
type Screen = 'title' | 'lobby' | 'game' | 'end'
type Phase = 'decide' | 'waiting' | 'results'
interface GameStore {
  screen: Screen
  mode: 'solo' | 'multi' | null
  config: Config
  state: GameState | null
  meId: string | null
  phase: Phase
  /** The state before the last resolution and after it, for the results sequence and map effects. */
  last: { before: GameState; after: GameState } | null
  startSolo(opts?: { seed?: number; name?: string }): void
  hasSave(): boolean
  resumeSolo(): boolean
  lockIn(): void               // solo: bots + resolveRound + save + phase 'results'. multi: net.submit
  finishResults(): void        // phase 'decide' (draft reset) or screen 'end'
  quitToTitle(): void
  // multiplayer hooks (src/net drives these)
  setRemote(state: GameState, meId: string): void
}

// src/store/draft.ts
interface DraftStore {
  decision: Decision
  past: Decision[]             // undo stack, cleared on reset
  reset(): void                // defaultDecision(state, meId)
  set(mutate: (d: Decision) => void): void   // pushes the previous decision on `past`
  undo(): void
  // thin helpers built on set(): setPower, setCompute, setRent, addBuild, removeBuild, toggleUpgrade,
  // setLoanTake, setRepay, toggleRefinance, setShares, toggleForcedSale
}
// src/store/derived.ts
useDerived(): { validation, preview, projection, warnings, risk }   // memoized on (state, decision)

// src/store/ui.ts
interface UiStore {
  panel: 'build' | 'allocate' | 'finance' | 'market' | null
  selected: string | null      // building id whose card is open
  drag: { order: BuildOrder } | null   // a build card being dragged onto the map
  settings: { theme: 'system' | 'light' | 'dark'; music: boolean; sfx: boolean; reducedMotion: 'system' | 'on' | 'off'; tutorial: boolean }
  tutorialStep: number | null  // 0..4, null when done or off
  open(p), close(), select(id), setDrag(d), setSetting(k, v), advanceTutorial()
}
```

Additions made by the shell (use them): game `goToLobby`, `setNetBridge`, `randomSeed`, `discardSoloSave`; draft `moveBuild` and an optional coalesceKey on `set`; ui `toggle`, `settingsOpen`, `forcedSaleConfirmed` / `confirmForcedSale`, `skipTutorial`, `maybeStartTutorial`, `replayTutorial`, `announce` / `liveMessage`, `resetPhase`. States returned by `resolveRound` share past history entries with the previous state: treat every state as read-only.

Local storage keys (all access in try/catch): `gt.solo.v1` (full GameState + meId), `gt.settings.v1`, `gt.tutorial.v1` (done flag), `gt.net.v1` (multiplayer token per room).

## 4. Screens (src/ui)

- `App.tsx` switches on `screen`: Title, Lobby (multiplayer waiting room), Game (map + top bar + panels + chips + results overlay), End.
- **Top bar** (always visible in game): Round x/40 with the season icon, treasury (teal), share price with an up/down arrow and its change, rank (#1 of 4), the projection line ("Next round ≈ +5.2"), mute toggle, menu, and the Lock in button (disabled with a reason when the draft is invalid). In multiplayer it also shows the countdown and who has locked in.
- **Panels** open over the map: a right-side sheet on desktop (≈ 380 px), a bottom sheet on phones (≤ 640 px wide). Tabs in spec order: Finance, Build, Allocate, Market (Review lives in the top bar + Market). Tab / Shift+Tab move between panels; Esc closes; keys 1–4 open them.
- **Chips** (warnings, never pop-ups) sit under the top bar: icon + word + value, colour + icon + text (never colour alone).
- **Building card**: tap a building on the map → MW, used, idle, status, countdown, Upgrade button (adds to the draft).
- **Results**: a full overlay after each lock in, animated in 4 beats (demand change per pool, revenue by pool, stock move as signed bars, new ranking), skippable, "Next round" button.
- **Forced sale**: replaces panels when treasury < 0: buildings with their 30% value, running total, Confirm enabled at ≥ 0 (or all sold).
- **End**: final ranking, SVG chart of every company's share price over 40 rounds, replay seed (copy), share card PNG (canvas, 1200×630) with download / Web Share.
- **Tutorial**: 5 steps over rounds 1–3 (allocate, build, read results, borrow, lock in), a small pointer bubble anchored to the relevant control; skippable; remembered.

## 6. Map and sprites (src/map, scripts/sprites)

- Sprites are generated by code (`scripts/sprites/*.mjs`, pngjs) into `public/sprites/atlas.png` + `atlas.json` (TexturePacker hash format that Pixi 8 `Spritesheet` reads: `frames`, `animations`, `meta`), plus a `points` object per frame name for anchors (chimney tops, turbine hubs, LED positions, crane hook). The generator also writes a 3× contact sheet to `app/.sim/sprites-preview.png` (git-ignored) for review.
- Sizes: tiles 32 × 32, small buildings 64 × 64, big ones 96 × 96, all drawn at native size and scaled by integers only with nearest-neighbour filtering (`TextureStyle.defaultOptions.scaleMode = 'nearest'`, `roundPixels`). 3/4 top-down view, 1 px dark outline on buildings only, 2–3 tones per material, soft shadow under buildings.
- Frame names (contract between art and map):
  - ground: `grass_{spring,summer,autumn,winter}_{0..3}`, `dirt_0..1`, `road_h`, `road_v`, `road_x`, `road_t_{n,s,e,w}`, `lot` (96 × 96 concrete pad), `fence_h`, `fence_v`, `flowers_0..2`, `tree_{spring,summer,autumn,winter}` (32 × 48), `bush_0..1`, `rock_0`.
  - plants: `plant_small` (64, solar field + a small wind turbine mast), `blades_0..3` (turbine rotor frames), `plant_big` (96, gas power station with a chimney and a cooling tower), `smoke_0..4` (16 px puffs), `shimmer_0..5` (solar glint overlay, 64).
  - datacenters: `dc_small` (64), `dc_big` (96), `rack_led_on`, `rack_led_dim` (2 × 2), LED positions in `points`.
  - building: `crane` (64 × 96), `scaffold_small` (64), `scaffold_big` (96).
  - town: `house_0..5` (32), `townhall` (64), `substation` (64), `pylon` (32 × 64), `pole` (16 × 32).
  - effects: `coin_0..5` (16), `spark_0..3` (8).
- Layout: the plot is 12 tiles wide (4 lots of 3 × 3 tiles) and `plotRows` lot rows tall, separated by a road row. The town (houses that multiply with your citizens share, 1 house per 0.5 MW used, up to the space) sits left of the plot; the substation (import link and other datacenters sales) sits right. Links are drawn as pole lines with yellow dots flowing at a speed scaled to their MW: internal (plants → datacenters along the road), town (plants → town), import (substation → datacenters), and power sold to other datacenters as dots running plants → substation with no line.
- Living map, each tied to a rule: smoke / blades / shimmer when a plant's output is used (still when idle); rack LEDs blink in proportion to used compute (dim when idle); crane with a floating countdown over anything building or upgrading (and a ghost crane while dragging a build card); houses multiply with the citizens share; coins pop over buildings at resolution (amount from `revenueByBuilding`); ground tint by season; day / dusk by theme.
- `src/map/CompanyMap.tsx` mounts Pixi in a div and exposes `mapApi` (module singleton): `lotAt(clientX, clientY): Tile | null`, `highlightLots(tiles: Tile[] | null)`, `focusBuilding(id)`, `playResolution(before, after)`. Camera: fit the plot to the viewport at the largest integer scale (2 or 3, 1 on tiny screens), pan by drag on phones.
- Reduced motion: no flow dots, no tweening, no smoke; LEDs static.
- **Frames added by the art pass** (all in atlas.json; overlays share their base frame's size and anchor): `path_v_0..1`, `path_h_0..1`, `path_end_{n,s,e,w}`, `path_x` (dirt paths in the town); `lot_marks` (corner marks, drawn only on free lots); `bush_winter_0..1`; `lamp` (16 × 32) and `glow_0` (24 × 24); `tarp_small`, `tarp_big` (tintable cover over a scaffold, orange for a plant, violet for a datacenter); `lights_{house_0..5, townhall, dc_small, dc_big, plant_small, plant_big, substation, lamp}` (dusk emissives); `snow_{house_0..5, townhall, dc_small, dc_big, plant_small, plant_big, substation, rock_0}` (winter caps). Points: every building/prop has `foot`; `plant_small.hub`, blades `center`, `plant_big.chimney` / `tower`, `dc_*.leds`, `crane.hook`, `house_N.chimney`.
- **Layering rules**: (1) season grass under `lot` and `path_*` (they have transparent edges); (2) `lot_marks` only on free lots; (3) at dusk draw `lights_*`, rack LEDs and `glow_0` after the dusk tint and untinted, in depth order with their building; (4) in winter draw `snow_<frame>` right after its building, use `bush_winter_*`, hide flowers; (5) wires are continuous 1 px ink lines with a 3 px sag; (6) weight grass variants 2–3 at about 60% and flip tiles for variety; (7) smoke frames are light: tint chimney smoke grey, leave cooling-tower steam white. The art agent's scene previews (`app/.sim/scene-*.png`, `app/scripts/sprites/preview.mjs`) are the reference composition.

## 7. Audio (src/audio)

WebAudio only, synthesized (no files). Extra exports: `audio.unlockOnFirstGesture(target?)`, `audio.close()`, `CUE_NAMES`. Loops are 16–24 bars. Apply the saved music/sfx settings before the first gesture, or a muted player hears music on the first click. `audio.unlock()` on first gesture, `audio.setSeason(0..3)` switches the soft chiptune loop (one per season, ~16 bars, square/triangle voices, low volume), `audio.cue(name)` for `lock`, `coins`, `crane`, `stockUp`, `stockDown`, `click`, `error`; `audio.setMusic(on)`, `audio.setSfx(on)`. Mute toggle in the top bar mutes both and is remembered.

## 8. Multiplayer (supabase/, src/net)

- Supabase Postgres + Realtime; resolution in the `grid-tycoon` edge function, which bundles the same engine (`npm run build:edge` → esbuild → `supabase/functions/grid-tycoon/engine.js`).
- Tables (RLS on): `gt_rooms` (code PK, seed, status lobby|playing|finished, host_seat, round, deadline timestamptz, seats int, fill_bots bool, state jsonb, updated_at) readable by anyone, written by the function only; `gt_players` (room_code, seat, name, is_bot, locked_round int, last_seen) readable; `gt_secrets` (room_code, seat, token_hash) and `gt_decisions` (room_code, round, seat, decision jsonb) not readable by clients at all. Realtime publication on `gt_rooms` and `gt_players`.
- Function actions (POST JSON `{ action, ... }`): `create { name, seats, fillBots }` → code + seat + token; `join { code, name, token? }` → seat + token (a token that matches a seat rejoins it; after start, a new name can claim a seat that has been away > 60 s); `start { code, token }` (host); `lock { code, token, round, decision }` (validated with the engine; resolves when every non-bankrupt human seat has locked); `tick { code }` (resolves if the deadline passed: missing players repeat last round's allocations with no builds or finance); `state { code }`. Resolution is guarded by `update ... where round = $expected` so it runs once.
- Client (`src/net`): `isOnline()` (false when no URL/key configured → the title screen says multiplayer is offline), `createRoom`, `joinRoom`, `startGame`, `submitDecision`, `subscribeRoom(code, cb)`, `tick`. Realtime presence on channel `gt:CODE` for who is connected. Server time offset from each response for the countdown. Config from `import.meta.env.VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`, falling back to `src/net/config.ts`.
